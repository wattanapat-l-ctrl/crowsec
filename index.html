📘 CrowdSec — ตรวจจับ SSH Brute Force บน AlmaLinux

§

ภาพรวมของระบบ

▾

เราจะสร้างระบบที่ช่วย จับ IP ที่พยายาม Login SSH ผิดซ้ำ ๆ แล้วบล็อกอัตโนมัติ

ส่วนประกอบ หน้าที่
1️⃣ CrowdSec Engine อ่าน Log และวิเคราะห์พฤติกรรมผิดปกติ
2️⃣ SSH Collection ตรวจจับเหตุการณ์ที่เกี่ยวข้องกับ SSH
3️⃣ Firewall Bouncer นำผลอนุมัติไปบล็อก IP ผ่าน Firewall

แผนผังลำดับการทำงาน

ผู้โจมตี Login SSH ผิดหลายครั้ง
↓
SSHD
↓
SSH Log
↓
CrowdSec Engine
↓
SSH Collection
↓
Alert
↓
Decision
↓
Firewall Bouncer
↓
Firewall Block
1.1

ดาวน์โหลดสคริปต์ติดตั้ง Repository ของ CrowdSec

bash
curl -s https://install.crowdsec.net | sudo sh
1.2

ติดตั้ง CrowdSec

คำสั่ง dnf install ใช้ติดตั้งตัว CrowdSec Engine -y
bash
sudo dnf install crowdsec -y
1.3

เปิดใช้งาน CrowdSec

enable = เปิดอัตโนมัติตอนบูตเครื่อง, --now = เริ่มทำงานทันที
bash
sudo systemctl enable --now crowdsec
1.4

ตรวจสอบสถานะ

bash
sudo systemctl status crowdsec

ผลลัพธ์ที่ควรเห็น:

active (running)
✅ ตรวจสอบสำเร็จถ้าเห็น active (running) แปลว่า CrowdSec ทำงานเรียบร้อย
ถ้าเห็น inactive / failed ให้ย้อนตรวจสอบขั้นก่อนหน้า
2

ติดตั้ง Collection สำหรับ SSH

▾

Collection เปรียบเสมือน "โมดูล" ที่บอก CrowdSec ว่าควรหาอะไรใน Log SSH

2.1

ติดตั้ง SSH Collection

Collection crowdsecurity/sshd มีกฎสำหรับตรวจจับการ Login ผิดซ้ำผ่าน SSH
bash
sudo cscli collections install crowdsecurity/sshd
2.2

ตรวจสอบ Collection

bash
sudo cscli collections list

ควรพบรายการ:

crowdsecurity/sshd
3

ตรวจสอบว่า CrowdSec อ่าน Log ได้

▾
3.1

ดูสถิติการอ่าน Log (Acquisition)

bash
sudo cscli metrics show acquisition

หรือดูภาพรวมทั้งหมด:

bash
sudo cscli metrics
✅ ตรวจสอบสำเร็จควรเห็น Log Source ของ SSH และ จำนวน Log ที่อ่านเพิ่มขึ้น แปลว่าระบบ Acquisition ทำงานถูกต้อง
4

ตรวจสอบ Alert และ Decision

▾
4.1

ดู Decision

Decision = "คำสั่ง" เช่น ให้ Ban IP นี้
bash
sudo cscli decisions list
⚠️ ข้อควรรู้ในตอนนี้ CrowdSec Engine แค่สร้าง Decision ยังไม่ได้บล็อก IP จริง — ต้องรอ Firewall Bouncer (ตอนที่ 7)
4.2

ดู Alert

Alert = "บันทึก" เหตุการณ์ที่พบว่าผิดปกติ
bash
sudo cscli alerts list
5

ทดสอบการตรวจจับ SSH Brute Force

▾
5.1

ทางลัด: จำลอง Login ล้มเหลวด้วย logger (ไม่ต้องมีเครื่องอื่น)

การใส่รหัสผ่านจริง ๆ ซ้ำ ๆ อาจช้าและผิดพลาด ให้ใช้คำสั่งนี้เขียนแถว Log SSH ปลอมลงในระบบแทน — รัน ติดกัน 5–6 ครั้ง เพื่อจำลองการ Login SSH ล้มเหลวจาก IP เดียวกันซ้ำ ๆ
bash 
logger -t sshd "Failed password for invalid user testuser from 198.51.100.50 port 54321 ssh2"

รันคำสั่งซ้ำ 5–6 ครั้งติดกัน เช่น:

bash 
logger -t sshd "Failed password for invalid user testuser from 198.51.100.50 port 54321 ssh2"
logger -t sshd "Failed password for invalid user testuser from 198.51.100.50 port 54321 ssh2"
logger -t sshd "Failed password for invalid user testuser from 198.51.100.50 port 54321 ssh2"
logger -t sshd "Failed password for invalid user testuser from 198.51.100.50 port 54321 ssh2"
logger -t sshd "Failed password for invalid user testuser from 198.51.100.50 port 54321 ssh2"
logger -t sshd "Failed password for invalid user testuser from 198.51.100.50 port 54321 ssh2"
⚠️ หมายเหตุวิธีจำลองนี้ใช้ได้เฉพาะการทดสอบเท่านั้น เพราะ Log ที่สร้างขึ้นอาจไม่ตรงรูปแบบ Native ของ SSHD 100% — ถ้าอยากได้ผลลัพธ์แม่นยำจริง ยังแนะนำให้ใช้การ Login จริงจากเครื่องอื่น (ขั้น 5.1)
5.2

กลับมาตรวจสอบ Alert

bash
sudo cscli alerts list
5.3

ตรวจสอบ Decision

bash
sudo cscli decisions list
✅ ตรวจสอบสำเร็จจะพบ Alert และ Decision ของ IP ที่มีพฤติกรรมน่าสงสัย
6

การปลดบล็อก IP

▾
6.1

ปลดบล็อก IP ที่ระบุ

bash
sudo cscli decisions delete --ip <IP_ที่ต้องการปลดบล็อก>

ตัวอย่าง:

bash
sudo cscli decisions delete --ip 192.168.1.100
6.2

ลบ Decision ทั้งหมด

bash
sudo cscli decisions delete --all
7

ติดตั้ง Firewall Bouncer

▾
💡 ทำไมต้องมี Bouncer? CrowdSec Engine แค่สร้าง Decision แต่ไม่บล็อก IP เอง — Bouncer คอยนำ Decision ไปสั่ง Firewall (nftables) ให้บล็อกจริง
7.1

ติดตั้ง Bouncer

bash
sudo dnf install -y crowdsec-firewall-bouncer-nftables
7.2

เปิดใช้งาน Bouncer

bash
sudo systemctl enable --now crowdsec-firewall-bouncer
7.3

ตรวจสอบสถานะ

bash
sudo systemctl status crowdsec-firewall-bouncer
active (running)
7.4

ตรวจสอบว่า Bouncer เชื่อมต่อกับ CrowdSec

bash
sudo cscli bouncers list

🧰 ชุดคำสั่งตรวจสอบระบบ (Cheat Sheet)

▾

เก็บไว้ใช้บ่อย ๆ — กดคัดลอกทั้งชุดได้:

bash
# ตรวจสอบสถานะ CrowdSec
sudo systemctl status crowdsec

# ตรวจสอบ Collection
sudo cscli collections list

# ตรวจสอบ Log Acquisition
sudo cscli metrics show acquisition

# ดู Alert
sudo cscli alerts list

# ดู IP ที่ถูก Ban
sudo cscli decisions list

# ดู Bouncer
sudo cscli bouncers list

# ตรวจสอบ Firewall
sudo nft list ruleset

สรุป + Checklist ส่งงาน

▾

ตารางสรุปหน้าที่ของแต่ละส่วนประกอบ

ส่วนประกอบ หน้าที่
CrowdSec Engine อ่าน Log และตรวจจับพฤติกรรมผิดปกติ
SSH Collection วิเคราะห์เหตุการณ์ที่เกี่ยวข้องกับ SSH
Alert แจ้งว่า CrowdSec ตรวจพบเหตุการณ์ผิดปกติ
Decision กำหนดการดำเนินการ เช่น Ban IP
Firewall Bouncer นำ Decision ไปบล็อก IP ผ่าน Firewall
Discord Notification ส่งการแจ้งเตือนไปยัง Discord
nftables Firewall ที่ใช้บล็อกการเชื่อมต่อ
🎯 สรุปสุดท้ายระบบทำงานอัตโนมัติตามลำดับ:
SSH Log → CrowdSec ตรวจจับ → Alert → Decision → Firewall Bouncer บล็อก IP → Discord แจ้งเตือน
